# 笔记内 Create 对话

## 产品范围

- 保留 `Note / Create / Record` 标签与现有全局 Chillo，不改变侧边栏入口。
- Create 默认以当前笔记作为资料，不额外显示 Current note，也不检索其他笔记。
- 三个标签共用固定的来源信息和标签栏，切换时不折叠顶部，也不把标题搬进导航栏。
- 空状态展示欢迎说明和四宫格技能，优先 Rewrite、Hook、Caption、Repurpose；输入框上方不显示快捷栏。发出第一条消息（文字或技能）后，四宫格消失，输入框左侧以低对比度星光图标提供技能入口，不显示快捷技能栏。缺少默认技能时按已添加列表补足，不重新添加已移除技能。欢迎标题旁的「…」或对话输入框左侧的星光图标打开技能列表，不再显示 All Skills 文字入口。选择技能后直接发送，回复仍出现在当前对话中。
- Create 左上角以悬浮小图标提供展开入口，不占用独立工具栏；全屏后在顶部提供收起按钮；全屏时隐藏笔记头部、来源与标签栏，继续使用同一个对话视图和状态，保留未发送输入与阅读位置。Android 系统返回先收起全屏。引导需要进入 Record 时自动收起，避免隐藏下一步入口。
- 笔记内对话仅保留文字输入，暂不提供语音输入。
- 点击技能立即发送，用户消息只展示技能图标、名称和标识，提示词不铺在界面里。
- 技能和普通提问共用聊天记录，AI 回答直接显示在对话中，不弹出独立技能结果页。
- 每条成功回复提供 `Use this`（用此版本），替换当前笔记正文，保留来源、标签与分区。
- 替换后保留对话并提供撤销。用户再次手动编辑正文后，旧撤销不覆盖新编辑。
- Translate 直接进入对话；未指定目标语言时由 AI 追问，不默认替用户选择语言。

## 新手引导

- 共 7 步，保留分享视频、打开笔记和阅读转录的步骤。
- 第 4 步打开 Create，第 5 步指向当前可见的技能入口（空状态四宫格或对话输入框左侧图标），点击直接发送；成功回复后，第 6 步提示进入 Record，第 7 步打开提词器。
- 不再单独提示继续聊天，也不要求替换笔记后才能继续。追问、替换和撤销仍可自由使用；录制始终使用笔记里实际保存的正文。
- 失败、取消或拒绝 AI 授权后可重试，不跳到录制。中断后根据本机对话恢复；兼容旧引导状态，不重置已完成或跳过的账号。

## 上下文与存储

- 每次请求包含当前笔记、最近最多 20 条对话轮次和用户的新请求。
- 后续技能由模型结合对话识别正在讨论的稿件或选项，不再把最后一条 AI 回复直接指定为草稿。历史携带技能类型及笔记版本是否匹配，分析和澄清问题不作为正文。若笔记正文已被改动，则默认从更新后的正文出发。
- 使用现有 Gemini 接口。笔记内使用独立的简短技能指令与公共对话规则，独立 Skills 入口保持原提示词，自定义技能原文保留。时长、平台、语气等设置作为默认参数，不能覆盖明确的对话要求；新对话轮次保存当时的默认参数，旧历史兼容读取。技能沿用 `agent_recipe` 用量，普通提问使用 `chat` 用量；本次不更改服务端扣费策略。
- 语言优先遵守明确约定；无约定时点击技能保留正文语言，主动输入的请求跟随用户语言，纯讨论不自动切换正文语言。
- 讨论记录按账号、笔记隔离保存在本机。重新进入同一笔记可以恢复；尚不跨设备同步讨论。
- 正文替换通过原有本地保存与同步流程完成。没有新增同步字段、服务端接口或数据库迁移。
- 取消或离开笔记后不接收迟到的回答；未完成的本机记录重新打开时可重试。
- 从笔记详情永久删除笔记时清理对应本机对话；删除账号时清理该账号的本机对话。

## 代码与验证入口

- iOS：`ios/chillnote/Features/NoteDetail/NoteConversation.swift`、`NoteConversationView.swift`。
- Android：`android/app/src/main/java/com/sponteoai/chillscript/ai/NoteConversation.kt`、`ui/editor/NoteConversationWorkspace.kt`。
- 单元测试：iOS `NoteConversationTests`；Android `NoteConversationTest`。
- iOS 交互测试：`NoteConversationUITests`，使用本机虚构笔记、内存数据库和模拟 AI 回复，不调用真实模型。
- iOS 调试预览参数：`-note-detail-design-preview -note-chat-design-preview`，直接打开 Create 空状态。

模型回复质量、线上额度变化和 Android 真机交互需要另外进行实际账号验收；模拟回复交互测试不等同于这些验收。
