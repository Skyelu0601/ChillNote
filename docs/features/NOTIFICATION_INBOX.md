# 首页通知入口

iOS、Android 首页搜索左侧提供铃铛，未读消息显示红点。点击进入独立通知列表，卡片直接展示全文，无详情页和跳转箭头。卡片仅用于告知，不含操作按钮；用途说明保持一句话。未读蓝点叠加在礼物图标左上角，不单独占据一列。

## 欢迎通知

- 迁移之前已存在的业务账号不补发欢迎通知。新建业务账号还需确认认证账号与业务账号的创建时间相差不超过 24 小时，避免把很久以前注册、首次使用后端的老账号当作新用户。
- `/notifications` 使用服务端最新的有效订阅状态，不使用 AI 额度的 tier 缓存。
- 免费用户只有在赠送记录可确认时才收到 `welcome_credits`。金额读取 `UserCredits.initialGrantAmount`，不使用剩余余额，也不在客户端写死 50。
- 新用户尚无额度记录时，在同一事务中创建额度和通知；已有额度不会再次发放。历史赠送金额未知时不推测、不发到账通知。
- 已付费新用户收到 `welcome_pro`。已有免费欢迎通知的用户升级后替换为会员欢迎内容，保留消息 ID、日期和已读状态；过期后不会重新赠送或重新亮红点。
- 每个账号的 `welcome` 去重键最多一条消息。消息与用户关联，删除账号时级联删除。

- 通知表启用 RLS，撤销 `anon` / `authenticated` 的直接访问权限；客户端只能通过已鉴权的后端读取和更新。

## API

- `GET /notifications`：鉴权必需，返回 `{ notifications: [{ id, kind, amount, createdAt, readAt, ... }] }`；只查询当前账号。
- `POST /notifications/read`：鉴权必需，请求 `{ ids: [UUID] }`，1–100 条；只更新当前账号拥有、尚未读的指定消息。重复请求安全，不会把随后才产生的消息标为已读。
- 只有列表中的卡片实际展示后客户端才发已读请求。成功响应后移除蓝点/红点；失败保留未读并提供重试。首页后台加载仅用于获取铃铛状态，不标记已读。
- 客户端忽略未知通知类型；接口暂不可用时显示加载失败与重试，不伪造到账消息。
- 原有 `/credits/balance`、`/credits/consume` 响应保持不变，旧客户端不需要调用新接口。
