# Chillo 第一版实现与上线检查

## 产品边界

Chillo 是基于用户已保存笔记进行创作的对话功能，不是陪伴角色。首页右上角原通知铃铛替换为 Chillo；搜索和底部录音、链接、新笔记按钮保持不变。侧边栏提供 Chillo 和通知，通知未读提示移至菜单。聊天页使用纯白背景、浅蓝用户气泡和无底色的助手回答。

Weekly Post Ideas 与 Create from Notes 的新版本移动端页面和入口已移除。保留旧报告的数据模型、兼容协议及相关解析测试，避免影响已有资料和旧版本客户端。根据用户对现有用户兼容性的要求，后台仍默认保留旧版周报任务和推送；只有另行决定退役并显式设置 `LEGACY_WEEKLY_TOPICS_ENABLED=false` 时才停止。这不是恢复新客户端的旧入口。

## 实现范围

- **知识库**：所有已同步、未删除、导入完成的 Inbox、Drafts 和 Published 笔记。未同步或仍在导入的内容不可凭空读取；界面显示可用笔记和索引进度。
- **授权**：打开页面不表示同意云端处理。用户首次启用时明确授权 Google Gemini 处理笔记索引、相关片段及对话记录，包括草稿。授权版本保存在账号下，可撤销；撤销会取消待生成任务并删除本服务保存的向量。索引保存、撤销授权和账号删除共用账号事务锁，避免撤销后旧任务又写回索引。已发往模型的在途请求无法撤回，但结果不会继续落库。
- **检索**：全文分段保留原文位置，按用户隔离分页检索整个笔记库，而非只取最近若干篇。文字匹配立即可用，后台逐步建立语义向量后混合排序。每篇最多取两个片段，模型可进行多轮搜索；自然语言支持日期、标签和分区条件。引用页可排除某个来源。固定来源的服务端协议已预留，第一版没有额外的手工选笔记面板。
- **生成**：沿用现有 Gemini 服务。笔记被明确视为资料而非指令；第三方收藏不代表用户立场或经历，Chillo 生成的草稿不作为独立事实依据。显示真实生成中状态，不模拟打字。当前接口轮询持久任务状态，完成后显示整段回答，尚不是逐 token 流式响应。
- **来源**：保存笔记 ID、内容指纹和片段位置，不另存过期原文副本。每次读取对话时重新核验来源。原笔记改动、进入回收站或被删除后，旧回答隐藏并提示重新提问。未知引用编号会移除。
- **对话**：跨设备保存在账号下；历史分页、继续对话、新建、取消、失败重试、删除均有接口和原生界面。最近 8 轮保留完整回答，较早至多 72 轮保留用户需求摘要片段；没有跨对话人格记忆。
- **草稿**：用户主动保存，写入 Drafts 并进入现有同步日志。相同回答重复保存返回同一份草稿，不覆盖用户后续编辑；删除过的草稿不自动复活。需要另一个版本时继续对话生成新回答再保存。删除对话不删除已保存草稿。
- **语音**：系统语音识别填入可编辑输入框；不自动发送，也不创建录音笔记。
- **额度**：沿用 chat 额度。生成完成、来源复核成功后，回答写入和一次扣费在同一事务中提交；取消、失败和内部检索不扣用户额度。持久任务租约支持服务重启后恢复。

## 代码位置

- 后端：`server/src/chillo.ts`（协议、任务、草稿、扣费）、`chilloSearch.ts`（权限与检索）、`chilloModel.ts`（模型适配）、`chilloCore.ts`（纯逻辑）。
- iOS：`ios/chillnote/Features/Chillo/`；接入现有 Home 导航和 SwiftData 笔记编辑器。
- Android：`android/app/src/main/java/com/sponteoai/chillscript/chillo/`；接入现有首页与笔记编辑器。
- 数据库：`server/prisma/migrations/20260917090000_chillo/migration.sql`。新增表和字段，不改历史迁移或客户端同步协议。笔记修改/软删除通过数据库触发器使向量立即失效。另增 `20260917093000_chillo_function_search_path` 固定函数的对象查找路径，没有改写已验证的原迁移。
- 新表启用 RLS 且不授予客户端策略，同时撤销 PUBLIC、anon 和 authenticated 的直接表权限；沿用后台特权连接。依据：[Supabase RLS 文档](https://supabase.com/docs/guides/database/postgres/row-level-security)。隔离 PostgreSQL 与正式 Supabase 均已验证四张新表启用 RLS，两种客户端角色均无直接读写权限。
